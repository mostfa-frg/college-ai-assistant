Making Resources Accessible
Goal 1
Types of Resources:
• Hardware: Printers, computers, storage.
• Software/Data: Files, web pages, databases.
• Networks: Internet, Wi-Fi, communication channels.
Reasons for Sharing:
• Economics: Save money (share 1 printer instead of 20).
• Collaboration: People can work together even when they are in different places.
(Google Docs, Zoom).
• Commerce: Support online services (Amazon, Banking).
Mechanism: Client-Server Computing
Clients request services from servers. For example, a web browser (client) requests web pages
from a web server. Servers manage resources and respond to client requests.
Resource Sharing: The ability to access hardware, software, and data across a network.

Goal 2: Transparency
Definition & Importance
Transparency is the ability of a distributed system to hide its distributed nature so that users 
understanding it as a single unified system.
Why is Transparency Important?
• Allows users to use the system without 
worrying about where resources are 
located.
• Makes programming easier by hiding 
network details.
• Enables system administrators to change 
hardware/software without affecting 
users.
• Provides a 'single system image'.
Transparency Hides:
• Where processes are located.
• Where resources are stored.
• How components communicate.
• Whether resources are replicated, or if 
components fail and recover.
• Whether multiple users access resources 
simultaneously.

Access Transparency
Enabling local and remote resources to be accessed identically
Access Transparency : Enables local and remote resources to be accessed using identical operations.
What it hides:
• Differences in machine architectures (e.g., Intel x86 vs. ARM).
• Differences in operating systems (e.g., Windows vs. Linux file paths).
• Differences in data representation (e.g., Big-endian vs. Little-endian, ASCII vs. Unicode).
How it is achieved:
• Middleware provides standard data representations (e.g., CORBA, JSON, XML).
• proxies translate local calls into request messages (A proxy acts as a helper that makes a remote 
service look like a local one). 
).
Example: provide the same required resources whether the files for example
inside the folder are stored on the local hard drive or on a remote network server.

Location Transparency
Accessing resources without knowledge of their location
Location Transparency : Enables resources to be accessed without knowledge of their physical 
location.
What it hides:
• The physical location (building, city, or IP address) of the server hosting the resource.
• The network route taken to reach the resource.
How it is achieved:
• Using logical names (e.g., URLs, domain names) instead of IP physical network addresses.
• Name services (like DNS) translate logical names to network IP addresses at runtime.
Example: www.google.com hides the actual server location .

Replication Transparency
Using multiple instances of resources without knowing
Replication Transparency: Enables multiple copies of resources to be used to increase reliability 
and performance without users or application programmers being aware of the duplicate copies.
Why we need Replication:
• Reliability: If one server fails, another replica can 
serve the request.
• Performance: Place a copy of the resource closer 
to the user (e.g., Content Delivery Network CDN).
• Load Balancing: Distribute requests among 
multiple replicas.
What it hides:
• The existence of multiple copies of a data 
object.
• The detail that a request might be routed 
to replica A today and replica B tomorrow.
Example: A user interacts with Google as if it were a single system, while the underlying 
infrastructure consists of many replicated servers that remain hidden from the user.
Note: A replica is a copy of a resource that contains the same 
data or functionality as another resource.

Migration Transparency
Allowing movement of resources and clients
Migration Transparency: Allows the movement of resources and clients within a system without 
affecting the operation of users or programs.
What it hides:
• That a resource has been moved from one 
physical location to another.
• That a client has moved to a new network 
or environment (e.g., mobile roaming).
How it is achieved:
• Using location-independent identifiers (e.g., 
A file keeps the same unique ID even after it 
is moved to a different server, so users can 
still find it without knowing its new 
location.).
• Employing forwarding pointers (When a 
mobile device moves to a new network, a 
forwarding service automatically redirects 
messages to the device's new location.).
Example: A person is talking on a mobile phone while traveling by train from London to Paris. The phone automatically 
switches between different cell towers and networks along the journey, so the call does not disconnect.

Failure Transparency
Concealing faults and allowing tasks to complete
Failure Transparency: Enables the hiding of faults, allowing users and application programs to 
complete tasks despite the failure of hardware or software components.
What it hides:
• That a server has crashed or a network link 
has failed.
• The recovery process (e.g., retransmitting 
lost messages).
• The switching over to a backup replica.
The Main Challenge
 •It is very difficult to distinguish between a 
dead resource and a still alive and 
functioning, but taking a very long time to 
respond
 •If a server doesn't reply, is it crashed, or 
just overloaded?
Example: A database transaction either fully completes or rolls back entirely(if the server crashes 
during processing time).

Goal 3: Openness
Extensibility and published interfaces
Benefits of Openness
• Interoperability: Components from different vendors work together.
• Portability: Applications can run on different systems without modification((run on multiple 
platforms)).
• Extensibility (easy to add/replace components).
Coulouris et al., 5th Ed.
Openness means that different systems and application can work together easily because they 
follow common standards and rules.
Simple Example
- A user can send an email from Gmail to Outlook because both email systems use common 
standards. This is an example of openness.
- A Windows computer can access a website hosted on a Linux server because both use standard 
Internet protocols. This demonstrates openness.

Scalability
Goal 4
Scalability: A system is scalable if it remains effective when the number of users and resources increases 
significantly.
Three Dimensions of Scalability:
1. Size Scalability: Add more users and resources easily (e.g., Netflix serving millions).
2. Geographical Scalability: Users and resources may lie far apart (e.g., global servers).
3. Administrative Scalability: Still easy to manage across multiple organizations (e.g., universities 
sharing resources).
Problem: A system scalable in one dimension often or may be has a loss of performance as it scales up.

Scaling Techniques (1/2)
Goal 4 · Scalability
Technique 1: Hide Communication Latencies
• Use asynchronous communication (send and continue working).
• Move computation to the client (e.g., JavaScript form validation instead of server-side).
Technique 2: Distribution (Partitioning)
• Split a large component into smaller parts and spread them across the system.
Example: DNS name space divided into zones, each handled by a single name server.
Example: Web is physically distributed across thousands of servers.
       Benefit: Divides the workload. No single server stores everything.
Technique 3: Replication and Caching
Replication: Make copies of data/services closer to users( Increases availability and balances 
load).
Caching: A special form of replication( Temporary copy made by client on demand).
       Benefits: Faster response, lower latency, reduced network traffic.

Goal 5: Reliability
Handling failures gracefully
Reliability : The ability of a system to continue operating correctly despite failures.
Techniques for Dealing with Failures:
Technique
Description
Detecting Failures
Using checksums to detect corrupted data; using timeouts to detect crashes.
Masking Failures
Retransmitting lost messages; storing data in multiple disks (RAID) to mask 
disk failure. 
Tolerating Failures
inform users and retry later if a server is unresponsive.
Recovery
Restoring consistent state using logs and rollback (e.g., in databases).
Redundancy
Using multiple routers, replicated DNS servers, or backup power supplies.
Availability: The time at which a system is available for use. 
RAID (Redundant Array of Independent Disks) is a technique that uses multiple disks

Case Study: The World Wide Web
Applying the 6 Goals
The Web is the ultimate large-scale distributed system. How does it meet our 6 goals?
Goal
How the Web Achieves It
Resource Sharing
Clients (browsers) request web pages from servers via HTTP. Shares information globally.
Transparency
Location Transparency: URLs hide IP addresses. Access Transparency: Same browser UI 
for all servers.
Openness
Based on published standards (HTTP, HTML, URL). Browsers and servers can be from any 
vendor.
Scalability
Uses DNS hierarchy for naming. Web Proxy Caching and CDNs (like Akamai) handle 
massive load.
Reliability
TCP protocol retransmits lost packets. Web farms replicate servers for high availability.
Performance
HTTP 2.0 and caching reduce latency. Browser opens multiple connections to fetch 
images in parallel.

Trade-offs Between Goals
Balancing competing requirements
It is impossible to perfectly achieve all goals simultaneously. Designers must make trade-offs.
Trade-off
Description
Transparency vs. 
Performance
When a system tries to hide the delay caused by communicating with 
remote servers, it often needs extra work and resources. This can 
make the system slower and more costly.
Reliability vs.
Performance
Reliability often requires acknowledging every message and keeping 
replicas in sync, which hurts performance.
Scalability vs. Security
When a system is spread across many computers and can grow 
easily, it becomes more difficult to control security
Openness vs. 
Performance
Using open and standard formats helps different systems work 
together, but it can make processing slower because extra work is 
needed to read and interpret the data.

Summary
1. The 6 main goals of distributed systems are Resource Sharing, Transparency, Openness, Scalability, 
Reliability, and Performance.
2. Transparency hides the distributed nature of the system. The 5 key types are Access, Location, 
Replication, Migration, and Failure.
3. Openness relies on published interfaces and middleware to allow heterogeneous systems to work 
together.
4. Scalability requires avoiding centralized bottlenecks by using techniques like DNS distribution, 
caching, and replication.
5. Reliability is achieved through failure detection, masking, tolerance, and redundancy.
6. Performance is measured by latency, throughput, and jitter. QoS guarantees are needed for real-
time multimedia.
7. Designers must constantly balance trade-offs between these goals (e.g., Transparency vs. 
Performance).
